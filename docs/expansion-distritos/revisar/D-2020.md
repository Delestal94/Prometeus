# D-2020 · Smoke del ejecutable en modo Empresa (`release.yml`) — revisar

## Probar a mano

- **La corrida en GitHub (lo que cierra la tarea).** El script nunca corrió en Linux. Después de subir la rama:
  `gh workflow run release.yml --ref <rama>` (sin `-f keep_builds`, así no queda ninguna build para bajar). Mirar en
  el job "Export Windows + Linux" que el paso "Smoke test (Linux build boots the company mode)" termine en
  `Empresa OK` y quede verde. Si falla, el artefacto `smoke-company-logs` (7 días) trae `menu.log`, `empresa.log` y
  `probe.log`. Lo que más puede pasar en Linux: que la carga del mundo en el runner tarde más que los 6000 cuadros
  del arranque (falla con "no escribió saves/company/company.json"), o un `ERROR` del log que en Windows no sale.
- La corrida manual no publica: el job `publish` solo corre con un tag empujado (`github.event_name == 'push'`) y
  los zips solo se suben como artefacto con un tag o con `keep_builds`. Verlo en la corrida: `publish` aparece
  salteado y no hay artefacto `builds-*`.
- En Windows ya dio `Empresa OK` con una build nueva de `main` (`builds/windows-d2020`), y el guardia corta un
  arranque colgado (`SMOKE_GUARD_SECONDS=8` → `Empresa FALLA: el arranque 'menu' no terminó en 8 s (salió con 124)`,
  sin proceso huérfano).

## Decidir al final

- **Guardia de 300 s en CI** (150 en la PC). Solo corta un arranque que nunca termina; el arranque en sí lo acota
  `--quit-after`. Si el runner resulta lento para cargar el mundo en 6000 cuadros, la salida es subir
  `COMPANY_FRAMES` (o hacerlo configurable), no la guardia.
- **`keep_builds` (falso por defecto).** Antes una corrida manual subía los zips como artefacto: en un repo público
  cualquiera con cuenta de GitHub los baja. Ahora hay que pedirlo. Si se quiere probar una build de una rama a mano,
  se marca la casilla y se acepta eso.
- **`publish` solo con un tag empujado.** Una corrida manual sobre la ref de un tag antes podía subir zips encima
  del borrador de ese tag (`--clobber`). Si alguna vez se quiere rehacer los adjuntos de un tag a mano, hoy hay que
  volver a empujar el tag.
- **El job de release no usa la build de Windows en el smoke de empresa.** El runner es Linux; la de Windows la
  prueba la rutina `pc-build` en la PC con el mismo script.
