# N-976 · Foto de entrega rechazada por el host queda marcada en el cliente — B · `Sonnet 5.5 · medium` · Aviso: no · **[x] #519**

Sección: 2. Programación y arquitectura técnica

Origen: revisión semanal 2026-10-19 (`auditor-red`, R-3, P3). `run_manager.gd:336-346`: el cliente marca `photo=true` antes de que el host conteste; si el host la rechaza por `PHOTO_REACH` (medido desde `reach_origin` en el host; ~2 m de diferencia a 70 km/h y 100 ms), el teléfono dice "guardada" y no deja repetir. Hecho cuando una foto rechazada por el host deja `photo=false` en el cliente y se puede repetir, probado en `test_run_manager_split.gd`.
- [x] **N-976.1** Arreglo recomendado: no marcar hasta que llegue `delivery_photo_taken` (sin RPC nuevo; si hace falta uno, protocolo según `docs/convenciones-godot.md` §6). Con `constructor-red`.
- [x] **N-976.2** Test en `test_run_manager_split.gd`. Con `escritor-tests`; tests `run_manager_split`.

Hecho (2026-10-19): el cliente ya no marca `photo` al disparar; solo `delivery_photo_taken` del host la marca. `RunDeliveries.ask_photo` deja una foto en vuelo 3 s por casa (`PHOTO_ASK_SECONDS`) y después se puede repetir si el host la rechazó. Sin RPC nuevo. Test en `test_run_manager_split.gd`. Límite: el teléfono sigue diciendo "guardada" en ese instante (el host no avisa rechazos sin un RPC nuevo).
